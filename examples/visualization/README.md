# Offline Bring example

These are fixture-based outputs, **not a recorded VLM or robot run**.
The input is `scene(found=True)` from `tests/test_search_recovery.py`: a fork,
robot, user, worktop, and drawer in KITCHEN, without invented metric coordinates.
The files were generated by `demo.spa_loop` in legacy dry-run mode with that
observation, empty initial memory, the real RoboKGNet interface, and the existing
Bring PDDL planner. Input and VLM transport were replaced with the test fixture;
no simulator, network inference, or ROS actions were executed.

- `scene_graph.json`: accumulated fixture memory, including observation evidence.
- `g1.json`: raw fixture observation and episode context.
- `g2.json`: actual PEL, frame grounding, and generated Bring plan.
- `g3.json`: dry-run action snapshot; `executed` is empty, not a success claim.

These files are static documentation artifacts. The demo does not load them.
From the repository root, with Python and rdflib installed:

```bash
python3 utils/view_kg.py examples/visualization/scene_graph.json --tree
python3 utils/view_kg.py examples/visualization/g1.json
python3 utils/view_kg.py examples/visualization/g2.json
python3 utils/view_kg.py examples/visualization/g3.json
python3 utils/view_kg.py schemas
```
